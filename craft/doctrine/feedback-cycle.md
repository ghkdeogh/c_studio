# 제작 피드백을 다음 작품에 반영하기

피드백의 정본은 각 작품의 feedback.json이다. 같은 내용을 전역 장부에 복제하지 않는다. 제작실의 “다음 작품에도 참고”는 여러 작품에서 scope=reusable인 기록을 모아 보여준다. 보관 상태는 공유 목록에서 제외한다.

## 새 작품을 시작할 때
1. `python -B _infra/creative-studio/production_assets.py lessons .`로 이전 작품의 재사용 기록을 읽는다.
2. 이번 장르·인물·카메라·모델에 맞는 적용 조건을 고른다. 과거 선호가 현재 사용자 요청보다 우선하지 않는다.
3. 적용할 기록의 출처 프로젝트·ID와 이번 적용 방법을 새 작품 feedback.json에 남긴다. 참고한 것과 실제 반영·검수한 것을 구분한다.
4. 인물은 characters.json과 연결된 시트를 확인한다. 참고 사진이 한 장뿐이면 완성 인물시트라고 표현하지 않는다.

## 제작·검수 중
- 기획을 건너뛰어 프롬프트 작성·영상 생성·작품 재개·검수로 들어와도 이 절차를 적용한다. 현재 작품 feedback.json과 `lessons .`의 최신 재사용 기록을 확인한다. 조회 실패를 “피드백 없음”으로 해석하지 말고 원인을 해결하거나 확인 불가를 보고한다. 같은 작업 중에는 이미 확인한 기록을 활용하되, 단계 전환이나 새 사용자 피드백이 있으면 변경분을 확인한다.
- 재사용 후보는 원본의 scope=reusable·적용 조건·현재 사용자 요청을 대조해 고른다. 현재 작품의 기록은 재사용 원본과 구분하고 자기 자신을 전작으로 보고하지 않는다. 다른 작품의 project 전용 지시를 전역 규칙으로 승격하지 않는다.
- 사용자 피드백: 관찰 또는 요청 / 다음에 할 행동 / 적용 조건 / 관련 컷·시각 / 출처를 기록한다.
- 사용자 발언, 결과 검수, 다른 제작자의 참고 자료를 origin으로 구분한다. 추측한 실패 원인을 사실로 기록하지 않는다.
- 컷 메모는 .studio에 그대로 보존한다. 사용자가 “피드백으로 정리”를 누르면 내용을 초안으로 가져오며 저장 전까지 별도 피드백 기록이 되지 않는다.
- 이 작품만의 연출은 scope=project. 다른 작품에도 유효한 작업 방식은 scope=reusable. 적용 조건을 반드시 설명한다.
- 수정은 같은 ID의 기록을 갱신하며, 동시 변경 충돌 시 오래된 창의 저장을 거절한다. 원본 미디어와 사용자 .studio 상태는 보존한다.

## 완료 후
결과 판정과 비용은 renders.md, 현재 진행점은 생성상태.md가 소유한다. feedback.json에는 결과를 바탕으로 배운 제작 행동과 정본의 위치를 남긴다. 반영함은 해당 작품에서 반영했다는 뜻이며 모든 미래 작품에 자동 적용됐다는 뜻이 아니다.

## 활용 근거를 남기는 기준

선택한 피드백은 현재 작품 feedback.json의 기존 필드로 추적한다. source에는 `productions/종류/원작품/feedback.json#기록ID`, action에는 이번 적용 컷과 구체적인 변경, context에는 적용 조건·현재 확인 단계·남은 검수, evidence에는 실제 변경 파일과 컷 ID 또는 검수 위치를 기록한다. 같은 항목을 단계마다 복제하지 않고 갱신하며 원본 피드백은 보존한다.

- 참고·적용 계획: status=open. 목록을 읽었다는 사실만으로 applied로 바꾸지 않는다.
- 대본·프롬프트·입력 반영: 해당 파일을 다시 읽고 실제 변경을 확인한 경우 applied로 기록할 수 있다. context에 `대본 반영 / 영상 검수 전`처럼 확인한 단계를 명시한다. 생성 전에는 선택한 피드백과 실제 제출 프롬프트·입력의 일치를 확인한다. 과거 버전의 evidence만으로 현재 버전도 반영됐다고 판단하지 않는다.
- 영상 검수: 실제 출력의 해당 컷·시각·소리를 확인하고 renders.md의 결과 판정을 연결한다. 미확인·실패·부분 반영은 context와 다음 행동에 남긴다. 대본에 적혀 있다는 이유로 완성 영상의 품질이나 게시 성과 향상을 확인했다고 보고하지 않는다.

기획·생성·검수 작업을 전달할 때는 전작에서 가져온 핵심 피드백과 이번 적용 위치, 아직 확인하지 못한 단계를 짧게 알린다. 맞는 후보가 없으면 없다고 알리고 억지로 적용하지 않는다. 후보를 제외한 이유가 다음 판단에 필요하면 생성상태.md의 다음 단계에 간단히 남긴다. 사용자에게 별도의 “이전 피드백도 활용해줘” 요청을 요구하지 않는다.
