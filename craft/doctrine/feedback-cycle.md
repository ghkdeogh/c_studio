# 제작 피드백을 다음 작품에 반영하기

피드백 원본의 정본은 각 작품의 feedback.json이다. 이번 작품에서 전작 원칙을 선택·적용·검수한 기록은 lesson-plan.json이 소유한다. 원문을 전역 장부나 새 작품으로 복제하지 않고 출처를 연결한다. 과거 feedback.json에 적힌 전작 적용 기록은 보존하되 새 추적 기록과 이중 집계하지 않는다.

## 새 작품을 시작할 때
1. `python -B _infra/creative-studio/production_assets.py lessons . --project productions/video/<id> --stage planning --limit 6`으로 이번 작품에 맞는 이전 피드백 후보를 읽는다. 작품 생성 전에는 --project 대신 --query로 장르·작업을 설명한다. 전체 원문을 출력하는 --raw는 기본 경로에서 사용하지 않는다.
2. 이번 장르·인물·카메라·모델에 맞는 적용 조건을 고른다. 과거 선호가 현재 사용자 요청보다 우선하지 않는다.
3. 적용할 기록의 출처 ref·source_hash, 이번 적용 방법·컷을 lesson-plan.json에 기록한다. 참고한 것과 실제 반영·검수한 것을 구분한다. 현재 사용자 요청과 BRIEF의 필수 조건은 추천 개수와 무관하게 확인한다.
4. 인물은 characters.json과 연결된 시트를 확인한다. 참고 사진이 한 장뿐이면 완성 인물시트라고 표현하지 않는다.

## 제작·검수 중
- 기획을 건너뛰어 프롬프트 작성·영상 생성·작품 재개·검수로 들어와도 이 절차를 적용한다. 현재 작품 feedback.json과 적용 기록을 확인하고 lessons의 --stage를 planning/generation/review로 지정한다. 모델 조건이 있으면 --model을 함께 지정한다. 조회 실패를 “피드백 없음”으로 해석하지 말고 원인을 해결하거나 확인 불가를 보고한다. 단계 전환이나 새 사용자 피드백이 있으면 변경분을 확인한다.
- 추천은 기본 6개이며 나머지는 --offset으로 조회한다. 조건 확인 후보 수가 있거나 추천이 부적절하면 --browse와 --query로 원문 조건을 비교한다. 단어 기반 점수는 의미 판단을 대신하지 않는다. 경고 후보를 검토 없이 생성 지시로 옮기지 않는다.
- 재사용 후보는 원본의 scope=reusable·적용 조건·현재 사용자 요청을 대조해 고른다. 현재 작품의 기록은 재사용 원본과 구분하고 자기 자신을 전작으로 보고하지 않는다. 다른 작품의 project 전용 지시를 전역 규칙으로 승격하지 않는다.
- 사용자 피드백: 관찰 또는 요청 / 다음에 할 행동 / 적용 조건 / 관련 컷·시각 / 출처를 기록한다.
- 사용자 발언, 결과 검수, 다른 제작자의 참고 자료를 origin으로 구분한다. 추측한 실패 원인을 사실로 기록하지 않는다.
- 컷 메모는 .studio에 그대로 보존한다. 사용자가 “피드백으로 정리”를 누르면 내용을 초안으로 가져오며 저장 전까지 별도 피드백 기록이 되지 않는다.
- 이 작품만의 연출은 scope=project. 다른 작품에도 유효한 작업 방식은 scope=reusable. 적용 조건을 반드시 설명한다.
- 수정은 같은 ID의 기록을 갱신하며, 동시 변경 충돌 시 오래된 창의 저장을 거절한다. 원본 미디어와 사용자 .studio 상태는 보존한다.

## 완료 후
결과 판정과 비용은 renders.md, 현재 진행점은 생성상태.md가 소유한다. feedback.json에는 결과를 바탕으로 배운 제작 행동과 정본의 위치를 남긴다. 반영함은 해당 작품에서 반영했다는 뜻이며 모든 미래 작품에 자동 적용됐다는 뜻이 아니다.

## 활용 근거를 남기는 기준

선택한 전작 피드백은 lesson-plan.json에서 출처별로 갱신하며 변경 이력을 보존한다. 원본의 source_hash와 실제 근거 파일의 변경을 확인한다. 상세 CLI·필드·복원 계약이 필요하면 `feedback-learning` 라우트로 [피드백 선별과 적용 기록](../../docs/studio/lesson-memory.md)을 읽는다.

- 참고·적용 계획: stage=planned. 조회만으로 적용 완료로 표시하지 않는다. 제외할 후보는 skipped와 이유를 기록할 수 있다.
- 대본·프롬프트·입력 반영: 실제 파일을 확인한 뒤 stage=applied와 파일 근거를 기록한다. 영상 검수와 구분한다. 생성 전 실제 제출 프롬프트·입력과 비교하고 과거 버전 근거만으로 현재 반영을 단정하지 않는다.
- 영상 검수: 출력의 해당 컷·시각·소리를 확인한 뒤 stage=reviewed, outcome=helpful/ineffective/uncertain을 기록한다. 등록된 영상과 renders.md가 모두 필요하다. application에는 판단 범위·남은 문제를 적는다. UI/CLI는 파일 연결과 변경 여부를 검사하며 실제 시청·청취를 대신하지 않는다.

## 작품이 쌓일 때 원칙 정리

동일한 행동과 적용 조건은 조회에서만 묶는다. 표현이 다른 기록은 원문과 조건을 확인한 뒤 learning.canonical_ref로 대표 원칙을 연결한다. learning의 주제·방침·키워드·제외 조건·모델·제작 단계를 사용하며 “60초 유지”처럼 특정 편 조건은 해당 범위로 좁힌다. 같은 주제의 다른 방침은 조건을 분리하고 임의로 최신 기록을 승자로 정하지 않는다.

검수 완료 후 lessons --stage review --browse로 달라진 적용 결과와 improvement_candidate를 확인한다. 서로 다른 작품의 유효한 helpful 기록이 2개 이상이고 ineffective가 없으면 원칙 정리 후보로 표시되지만 자동 승격하지 않는다. 복사본·동일 작품의 재시도·대본 반영만으로 성공 횟수를 늘리지 않는다. 후보의 원본과 실제 검수 근거를 읽고 재현 조건·예외를 정리해 learning을 갱신한다. 자료가 부족하면 후보로 유지한다. 실제 원문 변경은 사용자 의도와 원래 근거를 보존한다.

폐기할 원칙은 learning.state=retired로 기본 조회에서 제외하며 원문은 남긴다. 대체 원칙은 active와 supersedes 출처를 명시하고 적용 조건이 맞는 작업에서만 우선한다. 원칙 메타데이터와 적용 기록 모두 변경 이력에서 복원할 수 있다. 루트 AGENTS.md에 개별 교훈을 추가하지 않는다.

기획·생성·검수 작업을 전달할 때는 전작에서 가져온 핵심 피드백과 이번 적용 위치, 아직 확인하지 못한 단계를 짧게 알린다. 맞는 후보가 없으면 없다고 알리고 억지로 적용하지 않는다. 후보를 제외한 이유가 다음 판단에 필요하면 생성상태.md의 다음 단계에 간단히 남긴다. 사용자에게 별도의 “이전 피드백도 활용해줘” 요청을 요구하지 않는다.
